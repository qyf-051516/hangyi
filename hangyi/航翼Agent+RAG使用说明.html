航翼智能知识助手使用说明

适用于项目管理员、开发人员和小程序员工。当前版本已经完成业务知识入库、 检索、生成、引用、历史、反馈、配额和评测代码，并提供 30 类本地业务知识降级回答； 正式开放联网 RAG 前仍需完成环境部署与真实资料验收。

P0-P3 代码完成 Java Assistant 9004 30 道 Recall@5 评测 本地业务问答 30/30 普通员工与管理员分级

1. 助手现在能做什么

  • 回答航翼系统中的角色权限、排班、合规、调班、请假、资质、航班资料和管理员操作问题。
  • 回答只依据检索到的业务资料；没有足够依据时明确拒答。
  • 展示参考文档、章节和检索分数，引用由服务端生成。
  • 保存服务端历史和反馈，并按微信账号或 Web 账号隔离。
  • 普通员工默认每天 20 次，管理员默认每天 100 次。
助手暂不查询实时个人排班、航班最新状态或审批进度。遇到这类问题应打开对应业务页面。 KNOWLEDGE_AND_LIVE 当前会明确提示未启用，不会编造实时结果。

2. 首次部署顺序

数据库迁移
启动向量依赖
知识入库与评测
最后开启小程序

2.1 数据库

cd ../ideaprojects/hangyi
mysql -u root -p hangyi_scheduling < db/03-assistant-rag.sql

2.2 配置 Java 环境

复制 Java 项目的 .env.example 为 .env，填写下列关键参数：

ASSISTANT_INTERNAL_KEY=<openssl rand -hex 32>
QDRANT_API_KEY=<openssl rand -hex 32>
QWEN_API_KEY=<通义千问 API Key>
ASSISTANT_ENGINE_ENABLED=false
ASSISTANT_DEPENDENCY_PROBE_ENABLED=true

2.3 启动 Qdrant 和 Ollama

docker compose --env-file .env -f deploy/assistant/docker-compose.yml up -d
docker compose --env-file .env -f deploy/assistant/docker-compose.yml exec ollama ollama pull bge-m3

2.4 入库并评测

set -a
source .env
set +a

ASSISTANT_INGESTION_MODE=incremental \
ASSISTANT_EVALUATION_ENABLED=true \
./mvnw -pl hangyi-assistant spring-boot:run \
  -Dspring-boot.run.profiles=local

日志中的 Recall@5 默认必须达到 0.85。未达到门槛时不要打开问答开关。

2.5 启用 Java 问答

评测通过后设置 ASSISTANT_ENGINE_ENABLED=true，再正常启动 Assistant 和 Gateway。

3. 小程序配置

settings key上线值
assistantApiUrl公网 HTTPS Gateway origin，例如 https://api.example.com
assistantApiKey与 ASSISTANT_INTERNAL_KEY 完全一致
assistantEnabled控制联网 RAG，全部验收后改为字符串 "true"

重新上传 quickstartFunctions。云函数会根据当前 OPENID 生成可信员工身份和管理员状态。

不要配置 localhost、内网 IP、Docker 服务名、带路径 URL或自签证书地址。 小程序云函数只能访问证书有效的公网 HTTPS origin。

4. 员工怎么使用

  1. 先完成员工登录，进入“我的”页面。
  2. 点击“智能助手”。显示“内置业务知识可用”或“智能助手已就绪”后即可提问。
  3. 尽量提出具体业务问题，例如“调班申请会自动检查什么”。
  4. 查看回答下方的参考依据；生产操作仍以正式制度和管理员确认结果为准。
  5. 使用“有帮助”或“需改进”反馈，帮助后续修订知识。

公网 RAG 未配置或暂时不可达时，页面会自动使用内置业务知识，不会禁用输入框。内置模式回答稳定流程，不读取实时排班，也不会执行审批或数据修改。

客户演示建议依次提问：“调班申请怎么提交图片？”“系统如何校验资质和工时冲突？”“谁可以修改预计到达时间？”。如果问题超出已确认资料，助手应明确说明没有足够依据，不得猜测。

重新进入页面时会加载服务端历史，同时保留最近 20 条、7 天本地缓存。“清空本页”只清除当前设备显示，不删除服务端审计历史。

5. 如何让助手更懂真实业务

Java 知识库内置 6 份业务资料，小程序降级库覆盖 30 类稳定业务主题，但这些内容不等于单位全部正式制度。建议逐步补充：

  • 排班管理办法、值勤限制和交接班标准。
  • 勤务、放行、异常航班和应急处置程序。
  • 机型、发动机、航司授权和证照管理规则。
  • 调班、请假审批口径和常见驳回案例。
  • 员工真实常用问法、缩写和业务术语。

资料需先脱敏并转换为 UTF-8 Markdown，放入 Java 项目的 knowledge/business/，标记 EMPLOYEE 或 ADMIN 可见级别，然后重新执行增量入库和评测。

6. 故障检查

现象检查方向
当前使用内置业务知识这是可用的降级模式；如需完整 RAG，再检查 assistantEnabled、assistantApiUrl 和 assistantApiKey
助手配置不完整检查 assistantApiUrl 和 assistantApiKey
问答引擎配置不完整检查 Qwen Key、模型、Qdrant collection 与 embedding 配置
向量维度不一致确认 bge-m3 输出维度和 ASSISTANT_EMBEDDING_DIMENSION；更换模型后执行 full rebuild
知识库没有足够依据先换成更具体问法，再检查资料和 Recall@5 未命中题
今日次数已用完等待次日配额重置，或由部署人员评估配置，不要在客户端绕过

7. 下一阶段建议

优先增加“本人排班、航班最新状态、本人审批进度、本人资质”的只读工具。 实时结果直接查询 Core 或 Schedule，不写入 Qdrant；模型不能直接审批、授权或修改排班。
