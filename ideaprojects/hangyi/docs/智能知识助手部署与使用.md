# 航翼智能知识助手部署与使用

本文对应 `hangyi-assistant` 的完整 RAG 实现，适用于 Java Web 与微信小程序。助手只回答已入库业务资料，检索不到依据时拒答，不把实时航班或个人排班写进向量库。

## 一、组成

- `hangyi-assistant`：独立 Spring Boot 服务，默认端口 `9004`。
- Qdrant：保存业务知识分块向量，只绑定本机或内网。
- Ollama + `bge-m3`：生成中文与多语种 embedding。
- 通义千问 OpenAI 兼容接口：依据检索上下文生成回答。
- MySQL：保存会话、消息、反馈、每日配额和文档索引状态；Redis：按可信身份限制突发提问，保护外部模型配额。
- `knowledge/business/`：正式入库的业务资料。
- `knowledge/evaluation/questions.json`：30 道 Recall@5 检索验收题。

## 二、首次部署

### 1. 升级数据库

全新数据库直接导入：

```bash
mysql -u root -p < db/01-schema.sql
```

已有数据库先备份，再执行：

```bash
mysql -u root -p hangyi_scheduling < db/03-assistant-rag.sql
```

### 2. 配置环境变量

复制 `.env.example` 为 `.env`，至少填写：

```dotenv
JWT_SECRET=<与 gateway 相同>
ASSISTANT_INTERNAL_KEY=<openssl rand -hex 32>
ASSISTANT_INTERNAL_SIGNATURE_MAX_AGE=60s
QDRANT_API_KEY=<openssl rand -hex 32>
QWEN_API_KEY=<通义千问 API Key>
ASSISTANT_ENGINE_ENABLED=false
ASSISTANT_DEPENDENCY_PROBE_ENABLED=true
# 默认员工 10 次/60 秒、管理员 30 次/60 秒；Redis 不可用时助手会拒绝请求。
ASSISTANT_EMPLOYEE_MINUTE_LIMIT=10
ASSISTANT_ADMIN_MINUTE_LIMIT=30
ASSISTANT_RATE_LIMIT_WINDOW=60s
```

`ASSISTANT_INTERNAL_KEY` 必须与小程序云数据库中的 `assistantApiKey` 完全一致。云函数会用此密钥对每个 internal 请求的 HTTP 方法、路径与查询串、时间戳和可信员工身份作 HMAC-SHA256 签名；Java 仅接受时间差不超过 `ASSISTANT_INTERNAL_SIGNATURE_MAX_AGE` 的签名。部署主机应保持 NTP 时间同步，避免正常请求因时钟漂移被拒绝。密钥不能写进代码、知识文档或小程序包。

### 3. 启动向量依赖

```bash
docker compose --env-file .env -f deploy/assistant/docker-compose.yml up -d
docker compose --env-file .env -f deploy/assistant/docker-compose.yml exec ollama ollama pull bge-m3
```

Compose 默认只把 Qdrant `6333` 和 Ollama `11434` 绑定到 `127.0.0.1`。生产环境应为镜像固定经过验证的版本，不要直接把这两个端口暴露到公网。

### 4. 先做知识扫描

在项目根目录加载环境变量：

```bash
set -a
source .env
set +a
```

执行 dry-run：

```bash
ASSISTANT_INGESTION_MODE=dry-run \
./mvnw -pl hangyi-assistant spring-boot:run \
  -Dspring-boot.run.profiles=local
```

日志会输出扫描文档数、变化文档数、删除文档数和预计分块数。dry-run 不调用 embedding，也不修改 Qdrant。看到结果后可结束进程。

### 5. 增量入库并评测

```bash
ASSISTANT_INGESTION_MODE=incremental \
ASSISTANT_EVALUATION_ENABLED=true \
./mvnw -pl hangyi-assistant spring-boot:run \
  -Dspring-boot.run.profiles=local
```

首次执行会创建 `hangyi_business_knowledge` collection，批量生成向量并写入 Qdrant。评测默认要求 Recall@5 不低于 `0.85`；不达标时服务启动失败，并在日志列出未命中的题目 ID。

如果更换 embedding 模型或向量维度，必须执行全量重建：

```bash
ASSISTANT_INGESTION_MODE=full \
ASSISTANT_CONFIRM_FULL_REBUILD=true \
ASSISTANT_EVALUATION_ENABLED=true \
./mvnw -pl hangyi-assistant spring-boot:run \
  -Dspring-boot.run.profiles=local
```

全量重建会删除配置指定的 Qdrant collection。代码要求额外确认开关，避免误删其他集合。

### 6. 启用问答

入库和 Recall@5 验收通过后，把 `.env` 中的：

```dotenv
ASSISTANT_ENGINE_ENABLED=true
ASSISTANT_INGESTION_MODE=off
ASSISTANT_EVALUATION_ENABLED=false
```

再启动 Assistant 与 Gateway：

```bash
./mvnw -pl hangyi-assistant spring-boot:run -Dspring-boot.run.profiles=local
./mvnw -pl hangyi-gateway spring-boot:run -Dspring-boot.run.profiles=local
```

## 三、小程序接入

云数据库 `settings` 集合配置：

| key | 值 |
|---|---|
| `assistantApiUrl` | 公网 HTTPS Gateway origin，例如 `https://api.example.com` |
| `assistantApiKey` | 与 `ASSISTANT_INTERNAL_KEY` 一致 |
| `assistantEnabled` | 全部验收后改为字符串 `"true"` |

云函数只能访问证书有效的公网 HTTPS origin，不能配置 `localhost`、内网 IP、Docker 服务名、带路径 URL 或自签证书地址。

更新后重新上传 `quickstartFunctions`。小程序会通过云函数派生当前 OPENID、工号、姓名和管理员状态，不信任客户端自行传入的身份字段。

## 四、接口验收

内部状态：

```bash
curl -s http://127.0.0.1:9000/api/assistant/internal/status \
  -H "X-Internal-API-Key: $ASSISTANT_INTERNAL_KEY"
```

知识问答：

```bash
curl -s http://127.0.0.1:9000/api/assistant/internal/chat \
  -H "Content-Type: application/json" \
  -H "X-Internal-API-Key: $ASSISTANT_INTERNAL_KEY" \
  -H "X-Wechat-Openid: local-test-openid" \
  -H "X-Wechat-Employee-No: GH001" \
  -H "X-Wechat-Name: %E5%BC%A0%E4%BC%9F" \
  -H "X-Wechat-Is-Admin: true" \
  -d '{"question":"调班申请会自动检查什么？","mode":"KNOWLEDGE_ONLY"}'
```

响应应包含回答、服务端生成的 `sources`、会话标识和今日剩余配额。无相关资料的问题应返回“当前知识库没有足够依据”，且不调用生成模型补充常识。

## 五、维护业务知识

目前只接收 UTF-8 Markdown 或文本文件。新增单位正式制度时：

1. 把脱敏后的正式资料转换为 Markdown，放入 `knowledge/business/`。
2. 添加 front matter：

```yaml
---
title: 文件标题
version: 2026.08
visibility: EMPLOYEE
---
```

3. 普通员工可看的流程用 `EMPLOYEE`；仅管理员可看的管理制度用 `ADMIN`。
4. 按 H2/H3 组织章节，避免在单个章节混合多个无关主题。
5. 在 `knowledge/evaluation/questions.json` 增加真实员工问法和预期文档。
6. 先 dry-run，再 incremental + evaluation，验收通过后发布。

不要把身份证号、手机号、OPENID、内部密钥、个人实时排班或未脱敏事故材料放入知识库。

## 六、当前边界与下一阶段建议

当前 `KNOWLEDGE_ONLY` 已完整可用。`KNOWLEDGE_AND_LIVE` 会明确返回未启用，不会伪造实时结果。

下一阶段建议增加受控的只读业务工具：

- 查询本人今日或未来排班。
- 查询指定航班最新状态与预计到达时间。
- 查询本人调班和请假审批进度。
- 查询本人资质到期情况。

这些工具应直接查询业务服务，返回实时数据，并继续执行身份隔离、字段白名单、超时和审计；不应把实时结果长期写入 Qdrant。任何改排班、审批或人员授权能力都应继续由原业务页面完成，不让模型直接执行。
